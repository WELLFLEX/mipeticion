# Contribuir / Contributing

## Español

Gracias por ayudar a que las personas entiendan y ejerzan sus opciones.

Puedes:

- Corregir instrucciones de una entidad con una fuente oficial, fecha y pasos de verificación.
- Detectar barreras de lectura, teclado, lector de pantalla, zoom o uso móvil.
- Mejorar diseño o código, o revisar escenarios sintéticos.
- Participar en sesiones de usabilidad con consentimiento y sin publicar documentos personales.

Antes de cambiar el alcance, abre una propuesta breve. Para una corrección concreta puedes enviar un pull request directamente. Explica el problema, el comportamiento final y cómo lo comprobaste. Mantén el cambio acotado.

1. Sigue README.md para instalar y ejecutar.
2. Crea una rama; nunca subas credenciales ni borradores personales.
3. Lee AGENTS.md y las guías instaladas de Next.js antes de modificar rutas.
4. Ejecuta lint, typecheck y las pruebas pertinentes. Para flujos principales, ejecuta las pruebas de navegador.
5. Incluye capturas solo con datos sintéticos y describe cualquier limitación.

Las correcciones de directorio requieren URL oficial, fecha de revisión, alcance de la comprobación y diferencias respecto a la versión anterior. Que una URL devuelva HTTP 200 no demuestra que el canal permita radicar. No envíes peticiones de prueba a una entidad real para verificar el portal.

Ningún colaborador necesita acceso a casos privados. No pegues prompts, trazas o capturas que contengan datos personales en issues públicos. Reporta fallos de seguridad por SECURITY.md.

El código nuevo se aporta bajo Apache-2.0; las contribuciones al directorio derivado se aportan bajo CC BY-SA 4.0. Conserva las atribuciones de fuentes. No importes datos con una licencia desconocida. Participar implica seguir CODE_OF_CONDUCT.md.

## English

Contributions are welcome from developers, designers, accessibility testers and people who can verify official instructions. Read README.md for credential-free local setup.

Use synthetic examples only. Never upload personal petitions, credentials, screenshots with private data or production logs. No contributor needs access to private cases.

For directory corrections, include the official source URL, review date, verification scope and the exact changed instructions. HTTP success alone is not a working-channel check. Do not submit test complaints to real entities.

Keep pull requests focused; explain the final behavior and meaningful validation. Follow AGENTS.md and the bundled Next.js documentation, run lint/typecheck/tests and browser checks for citizen journeys. Ask maintainers about scope changes through an issue before expanding specialized legal workflows.

Code contributions are Apache-2.0; directory contributions follow CC BY-SA 4.0. Preserve upstream attribution and follow the code of conduct. Report security issues privately as described in SECURITY.md.
